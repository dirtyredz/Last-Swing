## Conventions

- **Commit identity:** `dirtyredz <dirtyredz@live.com>`. Never the work email.
- **Versioning:** bump `<Version>` in [`src/LastSwing.csproj`](src/LastSwing.csproj) only, only when
  publishing. Never hardcode a version in `Plugin.cs` (it's generated from the csproj). Current
  release: 1.0.0, with a committed-but-unreleased WIP feature on top — **do not publish** it.
- **Layout:** code lives under `src/game/` (live-game bridges), `src/ui/` (view + generated art) and
  `src/core/` (state/timing); only `Plugin.cs` sits flat beside the `.csproj` at the `src/` root
  (no `src/LastSwing/`). Docs + `pack.ps1` at the repo root. The homes are enforced — see
  [STRUCTURE.md](STRUCTURE.md)'s `## Layout` before adding a file.
- **Synced canonicals:** `Directory.Build.props` and `pack.ps1` are generated by
  `../../tools/sync-mod-files.ps1` — don't hand-edit them here.
- **Shared copies:** `src/game/GamePalette.cs` and `src/game/GameFonts.cs` are verbatim copies shared with
  sibling mods — fix bugs in all copies.
- **Read-only rule:** never `FindOrCreate` on any damage/persistence path (it writes the save).
- **No test project** — every path touches Unity/game types. [`TESTING.md`](TESTING.md) is the
  manual checklist; run it before shipping. **Do not launch the game** unless the user asks.

## Build

```bash
dotnet build src/LastSwing.csproj
```

Deploys the DLL to the local BepInEx plugins dir. `pack.ps1` → `dist/LastSwing-<version>.zip` for
release. Game path is set once in `Directory.Build.props`.

## Structure-review gate

This repo is gated (pre-push hook, installed 2026-08-22). Edit/debug freely — the review fires once
at **push** on the accumulated change, not per edit or per commit. Commit at logical boundaries;
Claude runs the review and pushes (asking first) when work is ready. `/gate status` shows what's
pending.
